## Part 1: Understanding Commit Classification

### What is Commit Classification?

Commit classification is the process of automatically categorizing git commits based on their content. This helps teams:

- **Track work types**: How much time is spent on bugs vs features?
- **Analyze patterns**: Are we refactoring enough?
- **Generate reports**: Automated release notes
- **Measure quality**: Bug fix ratio as a quality metric

### Classification Categories

We'll classify commits into 5 types:

1. **BUGFIX**: Fixes bugs or errors
   - Examples: "fix: resolve null pointer", "bugfix: handle edge case"

2. **FEATURE**: Adds new functionality
   - Examples: "feat: add user login", "implement payment gateway"

3. **REFACTOR**: Improves code without changing behavior
   - Examples: "refactor: simplify logic", "cleanup: remove dead code"

4. **TEST**: Adds or modifies tests
   - Examples: "test: add unit tests", "update test coverage"

5. **DOCS**: Updates documentation
   - Examples: "docs: update README", "add API documentation"

### Classification Approach

We'll use a **rule-based approach** with pattern matching:

1. **Conventional Commits**: Recognize patterns like "fix:", "feat:", "refactor:"
2. **Keyword Matching**: Look for words like "bug", "feature", "test"
3. **File Patterns**: Check file extensions (.test.js, README.md)
4. **Confidence Scoring**: Calculate how confident we are in the classification

**Why rule-based instead of ML?**
- Fast and deterministic
- No training data needed
- Easy to understand and debug
- Good baseline for future ML models
- Works well for conventional commits

## Part 2: Create Classification Schemas

### Step 1: Create classification.py Schema File

Create `app/schemas/classification.py`:

```python
from pydantic import BaseModel, Field
from typing import Optional, List
from enum import Enum


class CommitType(str, Enum):
    """
    Enumeration of commit classification types.

    Using an Enum ensures type safety and prevents typos.
    The str inheritance allows these to be serialized as strings in JSON.
    """
    BUGFIX = "BUGFIX"
    FEATURE = "FEATURE"
    REFACTOR = "REFACTOR"
    TEST = "TEST"
    DOCS = "DOCS"


class ClassifyRequest(BaseModel):
    """
    Request schema for commit classification.

    This defines what data the client must send when requesting
    a commit classification.

    Attributes:
        commit_message: The commit message text (required)
        files_changed: List of file paths that were modified (optional)
        diff_stats: Statistics about the diff (optional)
    """
    commit_message: str = Field(
        ...,
        description="Commit message text",
        min_length=1,
        max_length=5000
    )
    files_changed: Optional[List[str]] = Field(
        None,
        description="List of file paths changed in the commit"
    )
    diff_stats: Optional[dict] = Field(
        None,
        description="Diff statistics with additions and deletions"
    )

    class Config:
        """Pydantic configuration"""
        json_schema_extra = {
            "example": {
                "commit_message": "fix: resolve null pointer exception in user service",
                "files_changed": [
                    "src/services/user.service.ts",
                    "src/tests/user.test.ts"
                ],
                "diff_stats": {
                    "additions": 15,
                    "deletions": 8
                }
            }
        }


class ClassificationResult(BaseModel):
    """
    Response schema for commit classification.

    This defines what data the API returns after classifying a commit.

    Attributes:
        classification: The predicted commit type
        confidence: How confident we are (0.0 to 1.0)
        method: Which classification method was used
    """
    classification: CommitType = Field(
        ...,
        description="Predicted commit type"
    )
    confidence: float = Field(
        ...,
        ge=0.0,
        le=1.0,
        description="Prediction confidence score"
    )
    method: str = Field(
        default="rule-based",
        description="Classification method used"
    )

    class Config:
        """Pydantic configuration"""
        json_schema_extra = {
            "example": {
                "classification": "BUGFIX",
                "confidence": 0.92,
                "method": "rule-based"
            }
        }
```

**Understanding this code:**

1. **CommitType Enum**:
   - Defines valid commit types
   - `str` inheritance allows JSON serialization
   - Prevents typos (IDE autocomplete)

2. **ClassifyRequest**:
   - `BaseModel`: Pydantic base class for validation
   - `Field(...)`: Required field (the `...` means required)
   - `Field(None, ...)`: Optional field
   - `min_length=1`: Validation rule
   - `json_schema_extra`: Example for API documentation

3. **ClassificationResult**:
   - `ge=0.0, le=1.0`: Confidence must be between 0 and 1
   - `default="rule-based"`: Default value if not provided

4. **Config class**:
   - Provides example data for Swagger UI
   - Helps developers understand the API

**What Pydantic does automatically:**
- Validates data types
- Converts data types if possible
- Generates JSON schema for documentation
- Provides clear error messages
- Serializes to/from JSON

## Part 3: Implement Classification Model

### Step 2: Create classification.py Model File

Create `app/models/classification.py`:

```python
import re
from typing import Optional, List, Dict, Tuple
from app.schemas.classification import CommitType, ClassificationResult
import logging

logger = logging.getLogger(__name__)


class CommitClassifier:
    """
    Rule-based commit classifier using conventional commit patterns.

    This classifier uses regex patterns to match commit messages and
    file paths against known patterns for each commit type.

    The classification process:
    1. Score each commit type based on pattern matches
    2. Consider both commit message and file changes
    3. Select the type with the highest score
    4. Calculate confidence based on score distribution
    """

    def __init__(self):
        """
        Initialize the classifier with pattern definitions.

        Patterns are organized by commit type and use regex for matching.
        """
        # Message patterns for each commit type
        self.patterns: Dict[CommitType, List[str]] = {
            CommitType.BUGFIX: [
                r'\b(fix|bugfix|hotfix|patch)\b',
                r'\b(bug|issue|error|crash|exception)\b',
                r'\b(resolve|correct|repair)\b.*\b(bug|issue|error)\b',
                r'\b(null pointer|undefined|memory leak)\b'
            ],
            CommitType.FEATURE: [
                r'\b(feat|feature|add|implement|create)\b',
                r'\b(new|introduce|support|enable)\b',
                r'\b(functionality|capability|enhancement)\b'
            ],
            CommitType.REFACTOR: [
                r'\b(refactor|restructure|reorganize|rewrite)\b',
                r'\b(cleanup|clean up|simplify|optimize)\b',
                r'\b(improve|enhance)\b.*\b(code|structure|performance)\b',
                r'\b(extract|move|rename)\b.*\b(method|function|class)\b'
            ],
            CommitType.TEST: [
                r'\b(test|spec|testing)\b',
                r'\b(unit test|integration test|e2e|end-to-end)\b',
                r'\b(coverage|assertion|mock)\b',
                r'\b(add|update|fix)\b.*\b(test|spec)\b'
            ],
            CommitType.DOCS: [
                r'\b(docs|documentation|readme)\b',
                r'\b(comment|docstring|javadoc)\b',
                r'\b(guide|tutorial|example|usage)\b',
                r'\b(update|add|improve)\b.*\b(documentation|readme)\b'
            ]
        }

        # File extension patterns for each commit type
        self.file_patterns: Dict[CommitType, List[str]] = {
            CommitType.TEST: [
                r'\.test\.',
                r'\.spec\.',
                r'test_.*\.py$',
                r'.*_test\.py$',
                r'__tests__/',
                r'/tests?/'
            ],
            CommitType.DOCS: [
                r'\.md$',
                r'\.txt$',
                r'README',
                r'CHANGELOG',
                r'LICENSE',
                r'CONTRIBUTING',
                r'\.rst$',
                r'/docs?/'
            ]
        }

    def _score_message(self, message: str) -> Dict[CommitType, float]:
        """
        Score the commit message against all patterns.

        Args:
            message: Commit message text

        Returns:
            Dictionary mapping commit types to scores
        """
        message_lower = message.lower()
        scores: Dict[CommitType, float] = {ct: 0.0 for ct in CommitType}

        # Check each commit type's patterns
        for commit_type, patterns in self.patterns.items():
            for pattern in patterns:
                if re.search(pattern, message_lower, re.IGNORECASE):
                    scores[commit_type] += 1.0

        return scores

    def _score_files(self, files: List[str]) -> Dict[CommitType, float]:
        """
        Score the changed files against file patterns.

        Args:
            files: List of file paths

        Returns:
            Dictionary mapping commit types to scores
        """
        scores: Dict[CommitType, float] = {ct: 0.0 for ct in CommitType}

        for commit_type, patterns in self.file_patterns.items():
            for file_path in files:
                for pattern in patterns:
                    if re.search(pattern, file_path, re.IGNORECASE):
                        scores[commit_type] += 0.5

        return scores

    def _calculate_confidence(
        self,
        scores: Dict[CommitType, float],
        winner: CommitType
    ) -> float:
        """
        Calculate confidence based on score distribution.

        Confidence is higher when:
        - Winner has a high score
        - Winner's score is much higher than others

        Args:
            scores: Score dictionary
            winner: The winning commit type

        Returns:
            Confidence value between 0.0 and 1.0
        """
        total_score = sum(scores.values())

        if total_score == 0:
            # No patterns matched - low confidence
            return 0.3

        winner_score = scores[winner]

        # Normalize winner's score
        confidence = winner_score / total_score

        # Ensure confidence is in valid range
        return min(max(confidence, 0.0), 1.0)

    def classify(
        self,
        commit_message: str,
        files_changed: Optional[List[str]] = None,
        diff_stats: Optional[dict] = None
    ) -> ClassificationResult:
        """
        Classify a commit based on message and optional file changes.

        This is the main public method that orchestrates the classification.

        Args:
            commit_message: The commit message text
            files_changed: Optional list of changed file paths
            diff_stats: Optional diff statistics (not used yet)

        Returns:
            ClassificationResult with type, confidence, and method
        """
        # Score based on commit message
        message_scores = self._score_message(commit_message)

        # Score based on files (if provided)
        file_scores: Dict[CommitType, float] = {ct: 0.0 for ct in CommitType}
        if files_changed:
            file_scores = self._score_files(files_changed)

        # Combine scores
        total_scores: Dict[CommitType, float] = {
            ct: message_scores[ct] + file_scores[ct]
            for ct in CommitType
        }

        # Find best match
        if max(total_scores.values()) == 0:
            # No patterns matched - default to FEATURE
            classification = CommitType.FEATURE
            confidence = 0.3
        else:
            # Get commit type with highest score
            classification = max(total_scores, key=total_scores.get)
            confidence = self._calculate_confidence(total_scores, classification)

        logger.debug(
            f"Classified commit as {classification.value} "
            f"with confidence {confidence:.2f}"
        )

        return ClassificationResult(
            classification=classification,
            confidence=confidence,
            method="rule-based"
        )


# Global classifier instance (singleton pattern)
classifier = CommitClassifier()
```

**Understanding this code:**

1. **Pattern Dictionaries**:
   - `self.patterns`: Regex patterns for commit messages
   - `self.file_patterns`: Regex patterns for file paths
   - Organized by commit type for easy maintenance

2. **Scoring System**:
   - Message match = 1.0 point
   - File match = 0.5 points
   - Higher score = more likely classification

3. **_score_message()**:
   - Checks message against all patterns
   - Uses case-insensitive matching
   - Accumulates scores for each type

4. **_score_files()**:
   - Checks file paths against patterns
   - Lower weight than message (0.5 vs 1.0)
   - Files are secondary indicators

5. **_calculate_confidence()**:
   - Normalizes winner's score
   - Higher when winner dominates
   - Minimum 0.3 for no matches

6. **classify()**:
   - Main public method
   - Combines message and file scores
   - Returns structured result

7. **Global Instance**:
   - `classifier = CommitClassifier()`
   - Created once, reused everywhere
   - Efficient (no repeated initialization)

**Why this design?**
- **Extensible**: Easy to add new patterns
- **Testable**: Each method can be tested independently
- **Maintainable**: Clear separation of concerns
- **Efficient**: Patterns compiled once
- **Observable**: Logging for debugging

## Part 4: Create Classification Router

### Step 3: Create classification.py Router File

Create `app/routers/classification.py`:

```python
from fastapi import APIRouter, HTTPException
from typing import List
from app.schemas.classification import ClassifyRequest, ClassificationResult
from app.models.classification import classifier
import logging

logger = logging.getLogger(__name__)

# Create router with prefix and tags
router = APIRouter(
    prefix="/api/ml",
    tags=["classification"]
)


@router.post("/classify", response_model=ClassificationResult)
async def classify_commit(request: ClassifyRequest):
    """
    Classify a single commit based on its message and optional file changes.

    This endpoint analyzes a commit and returns its classification type
    (BUGFIX, FEATURE, REFACTOR, TEST, or DOCS) along with a confidence score.

    The classification is based on:
    - Commit message patterns (conventional commits, keywords)
    - File paths and extensions (if provided)
    - Diff statistics (if provided)

    Args:
        request: ClassifyRequest containing commit data

    Returns:
        ClassificationResult with type, confidence, and method

    Raises:
        HTTPException: If classification fails

    Example:
        POST /api/ml/classify
        {
            "commit_message": "fix: resolve null pointer exception",
            "files_changed": ["src/user.service.ts"]
        }

        Response:
        {
            "classification": "BUGFIX",
            "confidence": 0.92,
            "method": "rule-based"
        }
    """
    try:
        # Call the classifier
        result = classifier.classify(
            commit_message=request.commit_message,
            files_changed=request.files_changed,
            diff_stats=request.diff_stats
        )

        logger.info(
            f"Classified commit as {result.classification.value} "
            f"(confidence: {result.confidence:.2f})"
        )

        return result

    except Exception as e:
        logger.error(f"Classification error: {str(e)}", exc_info=True)
        raise HTTPException(
            status_code=500,
            detail=f"Classification failed: {str(e)}"
        )


@router.post("/classify/batch", response_model=List[ClassificationResult])
async def classify_commits_batch(requests: List[ClassifyRequest]):
    """
    Classify multiple commits in a single request.

    This endpoint is more efficient than making multiple individual requests
    when you need to classify many commits at once.

    Args:
        requests: List of ClassifyRequest objects

    Returns:
        List of ClassificationResult objects (same order as input)

    Raises:
        HTTPException: If batch classification fails

    Example:
        POST /api/ml/classify/batch
        [
            {"commit_message": "fix: bug in login"},
            {"commit_message": "feat: add dashboard"}
        ]

        Response:
        [
            {"classification": "BUGFIX", "confidence": 0.85, ...},
            {"classification": "FEATURE", "confidence": 0.90, ...}
        ]
    """
    try:
        results = []

        for i, request in enumerate(requests):
            try:
                result = classifier.classify(
                    commit_message=request.commit_message,
                    files_changed=request.files_changed,
                    diff_stats=request.diff_stats
                )
                results.append(result)

            except Exception as e:
                logger.error(
                    f"Failed to classify commit {i}: {str(e)}",
                    exc_info=True
                )
                # Continue with other commits even if one fails
                # Return a default classification
                results.append(ClassificationResult(
                    classification="FEATURE",
                    confidence=0.0,
                    method="error-fallback"
                ))

        logger.info(f"Batch classified {len(results)} commits")

        return results

    except Exception as e:
        logger.error(f"Batch classification error: {str(e)}", exc_info=True)
        raise HTTPException(
            status_code=500,
            detail=f"Batch classification failed: {str(e)}"
        )
```

**Understanding this code:**

1. **Router Setup**:
   - `prefix="/api/ml"`: All routes start with this
   - `tags=["classification"]`: Groups in documentation

2. **@router.post("/classify")**:
   - POST endpoint at `/api/ml/classify`
   - `response_model`: Validates and documents response
   - `async def`: Asynchronous for better performance

3. **classify_commit()**:
   - Takes `ClassifyRequest` (Pydantic validates automatically)
   - Calls the classifier
   - Logs the result
   - Returns `ClassificationResult`
   - Catches errors and returns HTTP 500

4. **classify_commits_batch()**:
   - Takes list of requests
   - Processes each one
   - Continues even if one fails (resilient)
   - Returns list of results in same order

5. **Error Handling**:
   - Try-except blocks catch errors
   - `HTTPException` returns proper HTTP error
   - `exc_info=True` logs full stack trace
   - Batch endpoint has fallback for individual failures

6. **Logging**:
   - Info level for successful operations
   - Error level for failures
   - Includes context (confidence, count)

**Why this design?**
- **RESTful**: Follows REST conventions
- **Resilient**: Handles errors gracefully
- **Observable**: Comprehensive logging
- **Efficient**: Batch endpoint for bulk operations
- **Documented**: Detailed docstrings for Swagger

## Part 8: Understanding the Complete Flow

### Request Flow Diagram

```
Client Request
    ↓
POST /api/ml/classify
    ↓
FastAPI Router (classification.py)
    ↓
classify_commit() function
    ↓
Pydantic validates ClassifyRequest
    ↓
CommitClassifier.classify()
    ↓
├─ _score_message() → Pattern matching
├─ _score_files() → File pattern matching
└─ _calculate_confidence() → Confidence calculation
    ↓
ClassificationResult created
    ↓
Pydantic validates response
    ↓
JSON response to client
```

### Data Flow Example

**Input:**
```json
{
  "commit_message": "fix: resolve null pointer in user service",
  "files_changed": ["src/user.service.ts", "src/user.test.ts"]
}
```

**Processing:**
1. **Message Scoring**:
   - "fix:" matches BUGFIX pattern → +1.0
   - "null pointer" matches BUGFIX pattern → +1.0
   - BUGFIX total: 2.0

2. **File Scoring**:
   - "user.test.ts" matches TEST pattern → +0.5
   - TEST total: 0.5

3. **Combined Scores**:
   - BUGFIX: 2.0
   - TEST: 0.5
   - Others: 0.0

4. **Winner**: BUGFIX (highest score)

5. **Confidence**: 2.0 / 2.5 = 0.80

**Output:**
```json
{
  "classification": "BUGFIX",
  "confidence": 0.80,
  "method": "rule-based"
}
```

## Part 12: Understanding Pattern Matching

### How Regex Patterns Work

**Basic Pattern:**
```python
r'\b(fix|bugfix)\b'
```

- `r'...'`: Raw string (backslashes treated literally)
- `\b`: Word boundary (start/end of word)
- `(fix|bugfix)`: Match either "fix" or "bugfix"
- `\b`: Word boundary

**Matches:**
- "fix: bug" ✓
- "bugfix in login" ✓
- "prefix" ✗ (no word boundary)

**Complex Pattern:**
```python
r'\b(resolve|correct)\b.*\b(bug|issue)\b'
```

- Match "resolve" or "correct"
- `.*`: Followed by any characters
- Match "bug" or "issue"

**Matches:**
- "resolve the bug" ✓
- "correct this issue" ✓
- "resolve bug" ✓
- "bug resolve" ✗ (wrong order)

### Adding Custom Patterns

To add your own patterns, edit `app/models/classification.py`:

```python
self.patterns = {
    CommitType.BUGFIX: [
        r'\b(fix|bugfix|hotfix|patch)\b',
        r'\b(bug|issue|error|crash)\b',
        # Add your custom patterns here:
        r'\b(broken|failing)\b',
        r'\b(regression|defect)\b',
    ],
    # ... other types
}
```

**Tips for good patterns:**
- Use `\b` for word boundaries
- Use `|` for alternatives
- Keep patterns simple
- Test with real commit messages
- Use case-insensitive matching
